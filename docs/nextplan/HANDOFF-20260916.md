## What was completed tonight

A read-only foundation, `manager/nextplan/`, that turns an AI agent's output
into a deterministic next action:

1. **Execution Plan V1 + lifecycle inventory** — where ADM actually stands
   between an agent stopping and the next step, measured from `main`'s code.
2. **Failure Atlas** — 53 machine-readable failure codes with detection
   signals, required evidence, safe default, finite budgets, reroute and
   human-gate policy, and defined behaviour once a budget is spent.
3. **AI result contract** — an agent report schema and ADM's normalized result,
   where every fact carries an evidence level bound to its source.
4. **Extraction** — native → fenced → deterministic → constrained heuristic →
   none, with a 28-case corpus.
5. **Verification** — read-only probes (git against a real repository, the ADM
   execution record, test evidence, Drive read-back, dispatch identity).
6. **NextPlan engine** — one action from a closed set, pure and deterministic.
7. **20-scenario matrix**, **atlas × planner cross-check**, **read-only
   pipeline**, **property and mutation tests**, **historical replay**,
   **governance drift audit**.

## Recommended read-only adversarial review scope for another AI

Start with the remediation itself (`fa847e3`, `096284d`): does the unconditional
"tests actually ran" item close CRITICAL 1 without blocking legitimate
completions, does exact-match verdict parsing lose any honest wording, and is
the contrary-prose rule too broad or too narrow? Then the original list:

1. `classify.completion_proof` + `planner.plan` — construct any input that
   reaches `MARK_COMPLETE` or `SEND_TO_REVIEW` without verified evidence.
2. `extract.py` — can agent text fabricate a REPORTED fact it does not support?
   Specifically: quoted or nested ```adm-result blocks, an agent echoing the
   prompt, payloads inside review findings.
3. `planner.plan`/`apply` — duplicate events, stale generations, reordering,
   and whether `generation` can be fooled; terminal-state immutability.
4. Budgets — any event sequence that consumes rounds forever, or a budget that
   resets when it should not.
5. `verify.py` — whether `GitProbe` can run a non-read-only command or be
   pointed at the wrong repository without a signal; whether
   `ExecutionRecordProbe` can mark a push VERIFIED without a real observation.
6. The atlas judgement calls: severities, budgets, and which failures are
   human-gated. These are design decisions, not facts, and deserve challenge.

The reviewer must not become the implementer.
